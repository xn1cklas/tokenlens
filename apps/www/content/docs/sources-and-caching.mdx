Tokenlens loads provider catalogs through the `catalog` option. This document explains how to pick the right hosted catalog, how to bring your own registry data, and how caching works. v2 does not bundle a generated static catalog; use caching for hosted sources and `SourceProviders`/`CatalogSource` when the data is user-authored or private.

## Built-in catalogs

Pass one of the supported identifiers to `createTokenlens({ catalog })` or the class constructor to opt into a hosted catalog. Omitting `catalog` falls back to the OpenRouter catalog when you instantiate `Tokenlens`; the module-level helpers continue to pass `"auto"` (an alias for OpenRouter) unless you override the `catalog` option.

| Catalog id    | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| `"auto"`      | Alias for the OpenRouter catalog (default for module-level helpers).        |
| `"openrouter"`| Live catalog fetched from OpenRouter.                                       |
| `"models.dev"`| Curated dataset derived from models.dev.                                    |
| `"vercel"`    | Live catalog from the Vercel AI Gateway.                                    |

Instance helpers cache the loaded catalog, so repeated method calls stay fast as long as the data remains fresh.

### Vercel source options

The Vercel catalog can also load endpoint metadata when you need richer routing information:

```ts
const tokenlens = createTokenlens({
  catalog: "vercel",
  sourceOptions: {
    vercel: {
      includeEndpointDetails: true,
      endpointConcurrency: 4,
    },
  },
});
```

### Per-call catalog selection

The module-level helpers (`getModelData`, `computeCostUSD`, etc.) accept an optional `catalog` property. This lets you reuse the shared helper instance while forcing a specific catalog on a single call:

```ts
import { computeCostUSD } from "tokenlens";

const costs = await computeCostUSD({
  modelId: "openai/gpt-4o-mini",
  catalog: "vercel",
  usage: { input_tokens: 1_000, output_tokens: 250 },
});
```

## Custom catalogs

When you need deterministic data (tests, offline tooling, demos), provide your own `SourceProviders` object. Passing a `SourceProviders` object bypasses remote fetching entirely; Tokenlens uses the structure you provide as-is.

```ts
import { createTokenlens } from "tokenlens";
import type { SourceProviders } from "tokenlens";

const fixtureCatalog: SourceProviders = {
  demo: {
    id: "demo",
    models: {
      "demo/chat": {
        id: "demo/chat",
        canonical_id: "demo/chat",
        name: "Chat Demo",
        cost: { input: 1, output: 1 },
        limit: { context: 128_000 },
      },
    },
  },
};

const tokenlens = createTokenlens({ catalog: fixtureCatalog });
```

## Async catalog sources

Use `CatalogSource` for registries you generate, host privately, or assemble from infrastructure at runtime. Tokenlens caches the loaded source the same way it caches hosted catalogs.

```ts
import { createTokenlens, type CatalogSource } from "tokenlens";

const privateRegistry: CatalogSource = {
  id: "private-registry",
  cacheKey: "tokenlens:private-registry",
  async load({ fetch = globalThis.fetch, signal } = {}) {
    const response = await fetch("https://example.com/models.json", { signal });
    return response.json();
  },
};

const tokenlens = createTokenlens({
  catalog: privateRegistry,
  ttlMs: 10 * 60 * 1000,
  timeoutMs: 3_000,
});
```

`id` identifies the source in diagnostics and default cache keys. Use `cacheKey` when multiple instances should share the same cache entry across process boundaries.

## Catalog overrides

Use `overrides` when you want a hosted catalog as the base but need local corrections, such as custom pricing, private model limits, or provider metadata that has not landed upstream yet. Override fields win over the base catalog; nested `cost` and `limit` objects are merged so you only need to provide the fields you want to change.

```ts
import { createTokenlens } from "tokenlens";
import type { CatalogOverrides } from "tokenlens";

const priceOverrides: CatalogOverrides = {
  openai: {
    models: {
      "openai/gpt-4o-mini": {
        cost: { input: 1, output: 2 },
      },
    },
  },
};

const tokenlens = createTokenlens({
  catalog: "openrouter",
  overrides: priceOverrides,
});
```

Overrides are patch-style: provider ids, model ids, and names default from the map keys when you add a new entry, while existing hosted metadata is preserved unless you replace a field. Omit `models` when you only need to patch provider metadata.

## Caching

Tokenlens caches the raw provider catalog to avoid repeated network calls. Returned values include any per-instance `overrides`, which are applied after reading from the cache. The default cache is in-memory with a 24h TTL.

### Key options

- `ttlMs`: cache duration in milliseconds (default `24 * 60 * 60 * 1000`). Set `ttlMs: 0` to disable Tokenlens' cache.
- `cacheKey`: unique identifier for the cached entry. When running multiple instances with different catalogs, specify unique keys to avoid collisions.
- `cache`: custom adapter implementing `{ get(key), set(key, entry), delete?(key) }` where `entry` is `{ value: SourceProviders; expiresAt: number }`, or `false` to disable Tokenlens' cache.
- `staleIfError`: return the last cached catalog when refresh fails (default `true`). Set to `false` when callers should observe refresh errors.

### Fetch controls

Hosted catalogs and async `CatalogSource` loaders receive the same fetch controls:

- `fetch`: custom fetch implementation for tests, edge runtimes, or instrumentation.
- `signal`: abort signal passed through to the fetcher.
- `timeoutMs`: timeout for catalog fetches.

```ts
const controller = new AbortController();

const tokenlens = createTokenlens({
  catalog: "vercel",
  fetch: instrumentedFetch,
  signal: controller.signal,
  timeoutMs: 5_000,
});
```

### Example: Redis-backed cache adapter

```ts
import { createClient as createRedisClient } from "redis";
import { createTokenlens } from "tokenlens";
import type { CacheAdapter, CacheEntry } from "tokenlens";

const redis = createRedisClient();
await redis.connect();

const redisCache: CacheAdapter = {
  async get(key) {
    const raw = await redis.get(key);
    return raw ? (JSON.parse(raw) as CacheEntry) : undefined;
  },
  async set(key, entry) {
    await redis.set(key, JSON.stringify(entry));
  },
  async delete(key) {
    await redis.del(key);
  },
};

const tokenlens = createTokenlens({
  cache: redisCache,
  cacheKey: "tokenlens:openrouter",
  ttlMs: 30 * 60 * 1000,
});
```

### No caching

Set `cache: false` to force Tokenlens to reload the catalog on every call and never return stale Tokenlens cache entries. `ttlMs: 0` has the same no-cache behavior.

### Error handling

If fetching the catalog fails and a cached value is available, Tokenlens returns the cached value instead of propagating the error. Set `staleIfError: false` to surface the error instead. To force a fresh load, call `Tokenlens#refresh(true)`.

## Refreshing & invalidation

Instances expose:

- `tokenlens.refresh(force?: boolean)`: reloads the catalog when the cache is stale, or immediately when `force` is true.
- `tokenlens.invalidate()`: clears the cache entry so the next call triggers a reload.

These hooks are useful when you know provider metadata has changed and you want the new values immediately.

## Summary

- Pick a built-in `catalog` (`"auto"`, `"openrouter"`, `"models.dev"`, `"vercel"`), supply your own `SourceProviders`, or provide an async `CatalogSource`.
- Use `overrides` for local price/limit corrections on top of a hosted catalog.
- Override `catalog` per call when using the shared helpers.
- Configure caching behaviour with `ttlMs`, `cache`, `cacheKey`, and `staleIfError`; use `cache: false` when an external framework owns caching.
- Configure network behaviour with `fetch`, `signal`, and `timeoutMs`.
- Use `refresh()` / `invalidate()` for manual control when needed.
