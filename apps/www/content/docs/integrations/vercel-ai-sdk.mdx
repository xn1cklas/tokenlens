title: "Vercel AI SDK Integration"
description: "Compute costs from Vercel AI SDK usage and attach metadata via middleware."
---

Tokenlens integrates seamlessly with the Vercel AI SDK by accepting AI SDK v5 `LanguageModelV2` and AI SDK v6 `LanguageModelV3` metadata. This guide shows you how to estimate costs from Vercel usage payloads and how to attach Tokenlens cost hints to SDK responses.

## Installing dependencies

Install Tokenlens, the Vercel AI SDK adapter, and the AI SDK provider packages you use. The examples below cover OpenAI, Anthropic, and xAI—install only the providers relevant to your project:

```bash
pnpm add tokenlens @tokenlens/vercel @ai-sdk/openai @ai-sdk/anthropic @ai-sdk/xai
```

> Tokenlens works with any provider supported by the Vercel AI SDK; the examples below cover OpenAI, Anthropic, and xAI.

## Estimating cost from a Vercel usage payload

```ts
import { computeCostUSD } from "tokenlens";
import { openai } from "@ai-sdk/openai";

// Define a model via the AI SDK.
const model = openai("gpt-4o-mini");

// Usage payload returned by the SDK.
const usage = {
  inputTokens: 1_000,
  outputTokens: 400,
  totalTokens: 1_400,
};

const costs = await computeCostUSD({
  modelId: model.modelId,
  provider: model.provider ?? model.providerId,
  usage,
});

console.log(costs.totalTokenCostUSD);
```

Tokenlens normalizes provider ids that include namespaces (e.g., `openai.responses`) and understands the AI SDK usage fields (`inputTokens`, `outputTokens`, `totalTokens`).

## Attaching cost metadata via middleware

Tokenlens provides middleware helpers for AI SDK v5 and v6 that add cost information to the `providerMetadata` of generated responses.

```ts
import { withTokenlens } from "@tokenlens/vercel";
import { createTokenlens } from "tokenlens";
import { anthropic } from "@ai-sdk/anthropic";
import { generateText } from "ai";

const tokenlens = createTokenlens();

const model = withTokenlens(
  anthropic("claude-3-5-sonnet-20241022"),
  tokenlens,
);

const result = await generateText({
  model,
  prompt: "Hello!",
});

console.log(result.providerMetadata?.tokenlens?.costs); // Token cost breakdown
```

The middleware calls `tokenlens.computeCostUSD` internally using the model metadata and usage provided by the SDK.

Use `withTokenlensV5` or `tokenlensMiddlewareV5` when you want explicit AI SDK v5 names, and `withTokenlensV6` or `tokenlensMiddlewareV6` for explicit AI SDK v6 names. The default `withTokenlens` helper follows the installed AI SDK major.

## Custom Tokenlens instances

If you need to pin a specific catalog or customise caching, create your own Tokenlens instance and pass it to the middleware or call its methods directly.

```ts
import { createTokenlens } from "tokenlens";
import { createOpenAI } from "@ai-sdk/openai";
import { withTokenlens } from "@tokenlens/vercel";

const tokenlens = createTokenlens({ catalog: "openrouter" });

const model = withTokenlens(
  createOpenAI({ apiKey: process.env.OPENAI_API_KEY })("gpt-4o-mini"),
  tokenlens,
);

// or provide fixture data directly (testProviders: SourceProviders)
const fixtureTokenlens = createTokenlens({
  catalog: testProviders,
  ttlMs: 0,
});
```

## Testing integrations

Use a fixture catalog during tests to avoid network variability:

```ts
import { createTokenlens } from "tokenlens";
import { withTokenlens } from "@tokenlens/vercel";
import { openai } from "@ai-sdk/openai";
import { testProviders } from "../fixtures/providers";

const tokenlens = createTokenlens({
  catalog: testProviders,
  ttlMs: 0, // always refresh in tests
});

const model = withTokenlens(openai("gpt-5"), tokenlens);
```

This isolates integration tests from external API fluctuations while ensuring Tokenlens still performs the same cost calculations as in production.

## Summary

- Tokenlens understands Vercel AI SDK model metadata (`modelId`, `provider`/`providerId`).
- Pass usage payloads directly to `computeCostUSD` or fetch metadata via `getModelData`.
- Use `@tokenlens/vercel` middleware to automatically compute costs when generating responses.
- Customise the catalog and caching (e.g., fixtures, TTL, cache adapter) via `createTokenlens` when needed.
