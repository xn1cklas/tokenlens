### Package Setup Status

This repository uses a conventional modern TypeScript package setup: pnpm workspaces, Turborepo, ESM-only packages, explicit `exports`, Changesets, npm provenance, Biome, Vitest, packed export smoke tests, and Node 20/22 CI.

## Current Baseline

- **Runtime policy**: Node.js 20+ is declared in package `engines` and validated in CI.
- **Publishing**: Changesets drives versioning and release PRs; the release workflow enables npm provenance.
- **Package metadata**: Publishable packages include repository, homepage, bugs, license, `publishConfig.access`, README, and package-local LICENSE files.
- **Exports**: Public packages expose root entrypoints, `./package.json`, and intentional subpaths such as `tokenlens/fetch`, `tokenlens/helpers`, `tokenlens/core`, and `tokenlens/tokenizer`.
- **QA**: CI runs lint, package/app/example build and typecheck, coverage-gated Vitest, and packed consumer export smoke tests.
- **Security hygiene**: Dependabot, `SECURITY.md`, `CONTRIBUTING.md`, PR template, and CODEOWNERS are present.

## Remaining Improvements

- Add type-level public API tests with `tsd`, `expect-type`, or a dedicated packed-consumer fixture for inference-heavy APIs.
- Add a bundle/size budget for the main `tokenlens` package so accidental runtime dependency growth is caught in CI.
- Document the Node LTS drop policy before the next runtime floor change.

## Rationale

The project should stay ESM-only and dependency-light in the main `tokenlens` package. Heavy integrations belong in optional packages, and release confidence should come from packed consumer tests rather than compatibility shims.
